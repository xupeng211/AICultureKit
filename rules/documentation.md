# 文档编写规范 (documentation.md)

## 🎯 文档理念

### 1. **用户导向**
- 文档为使用者服务，不是开发者的笔记
- 优先解决用户的实际问题
- 提供可操作的具体步骤

### 2. **保持同步**
- 代码变更时同步更新文档
- 文档与实际功能保持一致
- 定期审查文档的有效性

### 3. **结构清晰**
- 层次分明，便于导航
- 使用统一的格式和风格
- 提供目录和索引

### API文档
**格式要求**:
```markdown
### POST /api/users
创建新用户

**参数:**
- `name` (string, 必需): 用户姓名
- `email` (string, 必需): 邮箱地址
- `age` (integer, 可选): 年龄

**请求示例:**
```json
{
  "name": "张三",
  "email": "zhangsan@example.com",
  "age": 25
}
```

**响应示例:**
```json
{
  "id": 123,
  "name": "张三",
  "email": "zhangsan@example.com",
  "created_at": "2024-01-01T10:00:00Z"
}
```

**错误码:**
- `400`: 参数验证失败
- `409`: 邮箱已存在
```

### 代码注释规范
```python
def calculate_user_score(
    user_data: Dict[str, Any],
    weights: Dict[str, float] = None
) -> float:
    """计算用户综合评分。
    
    根据用户的各项指标和权重计算综合评分，
    用于用户等级评定和推荐系统。
    
    Args:
        user_data: 用户数据字典，包含各项指标
        weights: 权重配置，默认使用系统配置
        
    Returns:
        0-100之间的评分，越高表示用户质量越好
        
    Raises:
        ValueError: 当用户数据缺少必需字段时
        
    Example:
        >>> user = {"activity": 0.8, "quality": 0.9}
        >>> score = calculate_user_score(user)
        >>> print(f"用户评分: {score}")
        用户评分: 85.0
    """
```

## 🔄 文档维护

```bash

### 文档审查清单
- [ ] **准确性**: 信息是否与实际代码一致
- [ ] **完整性**: 是否涵盖所有必要信息
- [ ] **可用性**: 用户能否按照文档成功操作
- [ ] **可读性**: 语言是否清晰易懂
- [ ] **格式**: 是否符合项目规范

# 生成API文档

# 构建文档网站
make docs-build

## 📖 写作风格

### 语言要求
- **简洁明了**: 避免冗长的句子和复杂的术语
- **主动语态**: "用户可以..."而不是"可以被用户..."
- **具体准确**: 提供具体的数字、步骤、示例
- **一致性**: 术语和格式保持统一

### 用户体验
- **站在用户角度**: 考虑用户的背景和需求
- **循序渐进**: 从简单到复杂，逐步深入
- **提供上下文**: 说明为什么要这样做
- **预期结果**: 告诉用户应该看到什么

### 常见问题避免
- ❌ 假设用户了解内部实现
- ❌ 只描述功能，不提供使用方法
- ❌ 使用过于技术化的语言
- ❌ 缺少实际可运行的示例
