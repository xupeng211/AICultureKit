## 🎯 **项目开发核心原则**

### 1. **代码质量优先**
- ✅ **禁止随意创建新文件** - 除非任务明确要求
- ✅ **修改已有文件前自动备份** - 备份到 `backup/` 目录
- ✅ **每个新功能必须写单元测试** - 测试覆盖率 >= 80%
- ✅ **遵守项目已有代码风格** - 使用black格式化
- ✅ **优先复用已有函数/模块** - 避免重复造轮子

### 2. **开发流程规范**
- 🔄 **每次生成代码前加载项目上下文**
- 🧪 **lint & test 必须通过才能提交**
- 📝 **commit message遵循conventional commits**
- 🚀 **所有命令都通过 Makefile 统一执行**

### 3. **错误处理与安全**
- 🛡️ **必须处理异常和边界情况**
- 📋 **写结构化日志便于排查错误**
- 🔒 **使用typing进行类型注解**
- ⚡ **关键路径添加断言检查**

## ⚡ **开发流程检查点清单**

### 🚀 **任务启动前**
- [ ] **激活虚拟环境** - `source venv/bin/activate`
- [ ] **确认依赖完整** - 检查requirements.txt中的包
- [ ] **切换到feature分支** - 避免直接在main分支开发
- [ ] **拉取最新代码** - `git pull origin main`
- [ ] **加载项目上下文** - `python scripts/context_loader.py`
- [ ] **验证开发环境** - `make setup`

### 📋 **开发准备前**
- [ ] **备份要修改的文件** - 自动备份到backup/目录
- [ ] **了解相关模块和依赖** - 分析现有代码结构
- [ ] **检查是否有可复用代码** - 避免重复造轮子
- [ ] **确认任务分解合理** - 大任务拆分为小模块

### 💻 **开发过程中**
- [ ] **编写单元测试** - 新功能必须有对应测试
- [ ] **添加类型注解** - 提升代码可读性和维护性
- [ ] **添加异常处理** - 考虑边界条件和错误场景
- [ ] **添加中文注释** - 解释设计意图与核心逻辑
- [ ] **添加结构化日志** - 便于调试和监控
- [ ] **资源安全检查** - 网络、文件、数据库操作安全边界

### 🔍 **开发完成后**
- [ ] **自动代码格式化** - `make format`
- [ ] **代码风格检查** - `make lint`
- [ ] **类型检查** - `make type-check`
- [ ] **运行单元测试** - `make test`
- [ ] **测试覆盖率检查** - `make coverage`
- [ ] **安全扫描** - `make security`

### 🚀 **提交准备前**
- [ ] **本地CI预演** - `make prepush`
- [ ] **所有检查通过** - 质量检查器运行成功
- [ ] **小粒度commit** - 只包含本次任务的改动
- [ ] **commit message规范** - 遵循conventional commits
- [ ] **更新相关文档** - README、API文档等

## 🚀 **快速上手流程**

### 新团队成员入门：
1. 📖 **阅读本文件** - 了解整体规则架构
2. 📋 **查阅具体规范** - 根据工作内容阅读对应规则文件
3. 🔧 **设置开发环境** - 运行 `make setup`
4. 🧪 **验证环境** - 运行 `make test`

### 日常开发流程：
```bash
# 1. 开始开发前
make setup              # 初始化环境
make prepush            # 本地CI检查

# 2. 开发过程中
make format             # 代码格式化
make test               # 运行测试
make lint               # 代码检查

# 3. 提交代码前
make ci                 # 完整CI检查
git add . && git commit -m "feat: 新功能描述"
git push                # 推送代码
```

## 🚨 **严格禁止的行为**

- ❌ **提交未测试的代码** - 所有代码必须有测试覆盖
- ❌ **硬编码敏感信息** - 使用环境变量管理配置
- ❌ **忽略异常处理** - 必须处理所有可能的异常
- ❌ **创建过于复杂的函数** - 圈复杂度不得超过10
- ❌ **使用过时的Python特性** - 保持Python 3.11+兼容
- ❌ **不写注释的复杂逻辑** - 复杂逻辑必须有中文注释
- ❌ **绕过预提交检查** - 所有代码必须通过质量检查
- ❌ **随意创建目录结构** - 严格遵循既定目录规范
